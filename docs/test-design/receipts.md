# Receipts

Design only. No test code until this table is approved.

Scope is `POST /purchase-orders/{poId}/receive`. Create, submit, and GET appear only as setup or as a precondition for a later receive.

The api project already resets once before the suite (`tests/api/reset.setup.ts`). These rows do not call `POST /admin/reset`. Each row creates the records it reads and uses ids from its own responses. A row does not depend on execution order or on a record created by another row. Seed vendor `vnd-001` is the active vendor from the documented seed data. Create and receive send `Content-Type: application/json` and a JSON body, except RCV-33. Submit sends no body and no `Content-Type`.

Two purchase-order bodies are reused below. They are the same bodies as `docs/test-design/purchase-orders.md`.

The one-line body:

```json
{ "vendor_id": "vnd-001", "line_items": [{ "sku": "LUM-2X4-8", "quantity": 10, "unit_price": 4.75 }] }
```

The worked example (`docs/API.md` Purchase orders):

```json
{
  "vendor_id": "vnd-001",
  "line_items": [
    { "sku": "LUM-2X4-8", "description": "2x4 stud, 8 ft", "quantity": 10, "unit_price": 4.75 },
    { "sku": "CEM-30KG", "quantity": 4, "unit_price": 11.9 }
  ]
}
```

The curl receipt (`docs/API.md` Purchase orders):

```json
{ "items": [{ "sku": "LUM-2X4-8", "quantity": 10 }] }
```

Documented contract:

- Receive returns 200 and a `PurchaseOrder`. OpenAPI assigns 201 to vendor create, purchase-order create, and invoice create. Receive is 200 (`docs/QUESTIONS.md` A.2). The response schema is `PurchaseOrder`: `id`, `vendor_id`, `status`, `line_items`, `ordered_value`, `received_value`, `fully_received`. Each line includes `sku`, `description`, `quantity`, `unit_price`, and `received_quantity`.
- The call records a delivery on a submitted PO. Every SKU must be on the PO. Deliveries can be partial. The PO closes when every line is fully received (`docs/API.md` The purchase-to-pay flow and Purchase orders). Statuses move only forward: `draft` → `submitted` → `closed`.
- A delivery that does not finish every ordered line stays short of that close condition, so these rows expect `status` `submitted`. A delivery that finishes every ordered line still returns 200 and a `PurchaseOrder`. Whether that same body has `status` `closed` is open (`docs/QUESTIONS.md` D.18). Those rows do not assert `status`.
- `received_quantity`, `received_value`, `fully_received`, and `ordered_value` are not asserted on a receive response. How they are defined is open (`docs/QUESTIONS.md` D.15). The create example's `received_quantity` 0 and the match example's `received_value` 95.1 belong to those other responses. They are not copied onto receive. `docs/QUESTIONS.md` C.1 is a hypothesis, not an expected result.
- `ReceiveRequest` requires `items`, at least one item. Each item requires `sku` (`minLength` 1) and `quantity` (`exclusiveMinimum` 0, `maximum` 10000). The item has no price field (`docs/QUESTIONS.md` A.4 and A.5). `docs/API.md` says the same quantity and price limits apply to deliveries and invoice lines. The quantity bounds are tested here. A price sent on a delivery item is an additional property (RCV-32), not a price-limit case.
- Invalid bodies are HTTP 400. `rule` is `validation_error` (`docs/API.md` Errors). The OpenAPI 400 text is "Invalid body, wrong status or over-receipt." Exact `detail` text is not asserted (`docs/QUESTIONS.md` D.10).
- Wrong status is rule 10, `workflow_gate`: receive only on a submitted PO. A draft is that case (RCV-23). A closed PO is also the wrong status, and any further positive quantity also exceeds the ordered quantity across deliveries. Which rule is returned is open (RCV-26).
- Over-receipt is rule 2, `receive_quantity_limit`: the received quantity of a line never exceeds its ordered quantity, across all deliveries. One unit more than ordered is RCV-21. A later delivery whose own quantity is within the order, but whose total with earlier deliveries is over the order, is RCV-22.
- Quantity 10001 is one over the delivery maximum and, on any valid PO, also over the ordered quantity. Which 400 rule is returned is open (RCV-25). It is not copied from the purchase-order create row that expects `validation_error` for 10001, because that call has no `receive_quantity_limit`.
- A 404 body has `detail` and no `rule` (`docs/API.md` Errors). OpenAPI 404 is "Purchase order not found."
- An empty `items` array is open. OpenAPI sets `minItems` 1. `docs/API.md` does not say an empty array is rejected (`docs/QUESTIONS.md` A.8.6). D.14 asks that question for purchase-order `line_items` only.
- A SKU that is not on the PO is open (`docs/QUESTIONS.md` D.17 and A.8.11). `docs/QUESTIONS.md` C.6 guesses HTTP 400. That guess is not an expected result. A repeated SKU in one receive is open (`docs/QUESTIONS.md` D.16).
- Rules 1, 3, 4, 5, 6, 7, 8, 9, and 11 are not rejections on this call. Rule 8 names invoice lines. The receive sentence "every SKU must be on the PO" does not name `invoice_line_validation`. `partial_receipt_flag`, `gl_balance`, and `vendor_exposure_math` have no rejection story (`docs/QUESTIONS.md` A.8.3).

## Open questions

1. Is `status` `closed` on the receive response that finishes the last line? (D.18, RCV-30)
2. How are `received_quantity`, `received_value`, `fully_received`, and `ordered_value` defined after a delivery? (D.15, RCV-31)
3. Can one receive repeat a SKU, and are those quantities added before rule 2? (D.16, RCV-29)
4. What status and `rule` are returned when the delivery SKU is not on the PO? (D.17, A.8.11, RCV-28). C.6 is not an expected result.
5. Are non-integer delivery quantities accepted? (D.3, RCV-36)
6. Are additional JSON properties rejected? A delivery item has no `unit_price`. (D.5, RCV-32)
7. What is returned when `Content-Type: application/json` is missing or the body is not JSON? (D.6, RCV-33)
8. Are query parameters ignored? (D.7, RCV-34)
9. What is returned for an empty or malformed `poId`? (D.8, RCV-35)
10. What status and `rule` are returned for an empty `items` array? OpenAPI sets `minItems` 1. `docs/API.md` does not. D.14 covers purchase-order `line_items` only. (A.8.6, RCV-27)
11. When the delivery quantity is 10001 on a line ordered for 10000, which rule is returned, `validation_error` or `receive_quantity_limit`? (RCV-25)
12. When a further delivery is sent after the PO is closed, which rule is returned, `workflow_gate` or `receive_quantity_limit`? (RCV-26)
